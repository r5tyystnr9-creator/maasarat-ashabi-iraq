# مسارات أعشاب العراق

متجر عربي RTL جديد، بلوحة إدارة وقاعدة بيانات SQLite فعلية. يبدأ بدون منتجات أو طلبات تجريبية. الصورة المرجعية تحدد أسلوب البطاقات الخضراء والبنية العامة؛ صور المنتجات والشعار والبانر تُرفع من لوحة الإدارة.

## التقنية والتشغيل

Node.js 24+، Express 5، SQLite المضمنة في Node، JavaScript وCSS بدون مرحلة بناء. المنتجات والأقسام والطلبات والإعدادات محفوظة في قاعدة البيانات. الصور محفوظة داخل `DATA_DIR/uploads`.

```sh
npm ci
npm start
```

قبل أول تشغيل، اضبط `ADMIN_USERNAME` و`ADMIN_PASSWORD` من إعدادات البيئة؛ كلمة المرور 12 حرفًا على الأقل. لا توجد كلمة مرور افتراضية. ينشأ المدير الأول مرة واحدة فقط وتُخزن كلمة المرور كـ bcrypt hash؛ تغيير متغيرات البيئة لاحقًا لا يغير حسابًا موجودًا. لا تشارك كلمة المرور في Git أو المحادثات. `PORT` افتراضيًا 3000، و`DATA_DIR` افتراضيًا `./data`. `.env.example` للتوثيق فقط؛ الخادم لا يحمّل ملفات `.env` تلقائيًا.

المسارات: `/` و`/products` و`/product/:id` و`/cart` و`/checkout` و`/admin`. صفحة الإدارة تعرض تسجيل الدخول للمستخدم غير المسجل، وAPI الإدارة محمية أيضًا. الجلسات HttpOnly وSameSite، صالحة 8 ساعات، مع حماية CSRF وتحديد محاولات الدخول. في الإنتاج تُرسل Cookies عبر HTTPS فقط.

## البدء بمحتوى حقيقي

1. سجّل الدخول من `/admin`.
2. أضف أقسامك، ثم المنتجات والسعر والمخزون والوصف والصور (PNG/JPEG/WebP، حتى 10 صور، 5MB لكل صورة).
3. حدد المنتجات المميزة لظهورها في الصفحة الرئيسية.
4. اضبط معلومات المتجر والشعار وأرقام الاتصال وواتساب (رمز الدولة مثل 964، دون مسافات) والرسالة الافتراضية.
5. اضبط البانر والألوان والخط ورسوم التوصيل الافتراضية أو رسوم كل محافظة وحقول المنطقة والملاحظات.
6. إدارة الطلبات تعرض كل معلومات العميل وبنود الطلب والأسعار المحفوظة وقت الطلب، مع تغيير الحالة والبحث.

يقرأ المتجر البيانات من API؛ تتحدث المنتجات والإعدادات عند التنقل وإعادة التحميل، وتُحدّث الصفحة المفتوحة تلقائيًا كل 15 ثانية. لا يُعاد رسم نموذج إتمام الطلب أثناء الكتابة. عند التأكيد يحسب الخادم الأسعار والتوصيل من قاعدة البيانات مجددًا، ويتحقق من المخزون ويحجزه داخل معاملة واحدة. السلة محلية لكل متصفح، والطلبات محفوظة في الخادم. الدفع عند الاستلام؛ لا توجد بوابة دفع إلكتروني.

## النشر على Render

`render.yaml` يوفر Blueprint جاهزًا للنشر، لكنه لا ينشر تلقائيًا. ارفع الكود إلى GitHub ثم أنشئ الخدمة من Blueprint أو اضبط نفس الخيارات يدويًا.

- Node 24.19.0، أمر البناء `npm ci --omit=dev`، التشغيل `npm start`، فحص الصحة `/api/health`.
- `NODE_ENV=production` و`DATA_DIR=/var/data/store`، ثم اسم المدير وكلمة مروره عبر إعدادات Render الآمنة.
- يلزم قرص دائم مركب على `/var/data` لحماية SQLite والصور عند إعادة النشر. خطة Starter في الملف مدفوعة؛ الخدمة المجانية ذات التخزين المؤقت لا تناسب البيانات الحقيقية لهذا التصميم.
- شغّل نسخة واحدة من الخدمة؛ SQLite والقرص المحلي لا يدعمان تعدد نسخ التطبيق هنا.
- Render يوفر HTTPS؛ لا تغيّر Secure cookies إلى false في الإنتاج.
- خذ نسخًا احتياطية من قاعدة البيانات بطريقة SQLite backup، وانسخ uploads أيضًا، واحتفظ بالنسخ خارج قرص الخدمة. لا تنسخ ملف SQLite وحده أثناء الكتابة دون آلية نسخ SQLite أو إيقاف الخدمة.

التنفيذ المحلي لا يثبت نجاح نشر Render. يجب التحقق بعد النشر من تسجيل الدخول ورفع الصور وطلب حقيقي تجريبي وحفظ البيانات بعد إعادة التشغيل.

## الاختبارات

```sh
npm run check
npm test
```

الاختبار يشغل خادمًا بقاعدة بيانات مؤقتة، ويستخدم Playwright ومتصفح Chromium لاختبار دورة المنتج والسلة والطلب وتغيير الحالة عبر الواجهة، ويفحص CSRF والصلاحيات والتلاعب بالأسعار والمخزون وحفظ البيانات بعد إعادة التشغيل. تُحذف بيانات الاختبار ولا تدخل المتجر الحقيقي. يحتاج Chromium المثبت في `/usr/bin/chromium` أو `CHROMIUM_PATH` يشير إلى متصفح محلي. على أجهزة أخرى يمكنك تثبيت Chromium بالطريقة الرسمية لنظامك.

## حدود التشغيل

إلغاء الطلب يغيّر الحالة فقط ولا يعيد المخزون تلقائيًا؛ حدّث المخزون من صفحة المنتج بعد التأكد من الإلغاء لتجنب إعادة مخزون طلب خرج للتوصيل. حذف المنتج لا يحذف تفاصيل الطلبات السابقة. لا توجد ادعاءات علاجية أو تقييمات زبائن وهمية. يجب إدخال الصور والأسعار والوصف الحقيقي من صاحب المتجر.

## طريقتا البيع وعروض الكمية

داخل إضافة/تعديل المنتج يوجد **طريقة البيع**: `normal` (كمية عادية) أو `offers` (عروض كمية). الكمية العادية تستخدم سعر القطعة والعدد كما في السابق. عروض الكمية تستخدم السعر الإجمالي للعرض، وليس سعر القطعة مضروبًا في العدد. يمكن إضافة حتى 20 عرضًا وتعديلها وحذفها وتغيير ترتيبها بأزرار ↑ و↓؛ لكل عرض معرف ثابت مستقل عن ترتيبه.

- API المنتجات يقبل `saleMode` و`quantityOffers`. كل عرض يحتوي `id` و`quantity` و`totalPrice` و`deliveryFee` و`freeDelivery` و`badgeText`. يُولّد الخادم معرفًا إذا لم يُرسل عند إنشاء العرض؛ احتفظ بمعرف العروض الموجودة عند تعديلها.
- عند بدء الخادم، يضيف ترحيل SQLite داخل معاملة حقلي `sale_mode` بقيمة `normal` و`quantity_offers` بقيمة JSON `[]` فقط إذا لم يكونا موجودين. لا تُحذف المنتجات أو الطلبات ولا تتغير أسعارها ومخزونها. إعادة التشغيل لا تعيد الترحيل المنفذ.
- تبقى المنتجات القديمة عادية تلقائيًا. تبديل المنتج إلى الكمية العادية يبقي عروضه المحفوظة غير نشطة لإمكانية الرجوع إليها. الطلبات القديمة التي لا تحتوي معلومات العروض تبقى قابلة للعرض.
- في السلة يُختار عرض واحد لكل منتج؛ إضافته مجددًا تستبدل اختياره السابق. تغيير عدد القطع يتم عبر اختيار عرض آخر، وليس زيادة عدد حزم العرض.
- طلب المنتج العادي يرسل `{id, quantity}`، والعرض يرسل `{id, offerId, quantity}`. الخادم يقرأ العرض من قاعدة البيانات، ويطابق كمية القطع، ويحسب السعر والتوصيل، ويتجاهل جميع الأسعار والرسوم المرسلة من المتصفح. العرض المحذوف/غير المعروف أو الكمية المتغيرة أو غير المتوفرة يُرفض دون خصم مخزون أو إنشاء طلب جزئي.
- **التوصيل في السلة المختلطة:** رسوم المنتجات العادية مرة واحدة حسب المحافظة، بالإضافة إلى رسوم كل عرض مختار. `freeDelivery` يجعل رسوم ذلك العرض صفرًا مهما كانت `deliveryFee` المحفوظة، ولا يلغي رسوم المنتجات الأخرى. إذا كانت السلة عروضًا مجانية فقط فالتوصيل صفر. رسوم العرض غير مرتبطة برسوم المحافظة.
- يُخصم عدد قطع العرض من المخزون داخل نفس معاملة إنشاء الطلب. تُحفظ نسخة كاملة من العرض واسمه/وصفه وسعره ورسومه وقت الطلب، ولا تؤثر تعديلات العروض اللاحقة في الطلبات السابقة.
- تعرض السلة أحدث أسعار العروض المتاحة. إذا تغيرت الكمية أو حُذف العرض أو تغير نوع البيع أو نقص المخزون، تطلب إعادة الاختيار وتحجب إتمام الطلب. إذا تغير المجموع أثناء التأكيد تظهر رسالة للمراجعة قبل محاولة التأكيد مجددًا.

اختبارات `tests/quantity-offers.test.js` تغطي ترحيل قاعدة قديمة، شراء قطعتين عاديتين، شراء عرض 3 قطع، الشحن المجاني والمختلط، منع تجاوز المخزون والتلاعب بالأسعار، حفظ الطلبات القديمة، وتعديل وترتيب وحذف العروض عبر المتصفح وتحديث صفحة المنتج المفتوحة تلقائيًا.
